# Final Handover Documentation — Reserved for Project Closeout

**Status:** Not yet prepared  
**Purpose:** This folder is reserved for the final as-built technical and operational documentation.

The initial project documents describe intended requirements and proposed architecture. They are not substitutes for the final system documentation.

The final handover pack must be written **after the product is implemented and tested**, using the actual source code, deployed platform settings, database schema, CMS workflows and verified recovery procedures. Do not copy a proposal into the final handover and present it as an implemented fact.

2. As-built system architecture and architecture decision records.

4. Exact runtime, framework and dependency versions.
5. Environment-variable register with names and setup instructions only.
6. Database ERD, schema, data dictionary and migration history.
7. Authentication, roles, permissions and account-recovery guide.
8. CMS administrator and editor operating manual.
9. Content workflow, media standards and publishing procedures.
10. Deployment, domain, DNS, certificate and rollback runbook.
11. Backup, export, restore and disaster-recovery runbook.
12. Security, privacy, logging and incident-response guidance.
13. Test report, release evidence and outstanding-issues register.
14. Third-party services, licences, ownership and renewal register.
15. Training materials, exercises, attendance/acceptance and FAQ.
16. Client ownership and access verification checklist.
17. Maintenance recommendations and optional future roadmap.

## Completion rule

Each document must describe implemented behaviour and include verification evidence or explicitly state its limitation. Any section that cannot be verified must be marked unknown or not tested. Do not claim training, backups, restore drills, security testing or production configuration has occurred unless records support the claim.
